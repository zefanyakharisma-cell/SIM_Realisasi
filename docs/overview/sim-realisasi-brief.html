SIM Realisasi Project Brief

SIM Realisasi records every activity that carries out one of PCU's MoUs and MoAs, has IO verify the mobility ones, and turns the verified data into the university's RENSTRA indicators and the International Awards rankings, with frozen semester reports that never change after the fact.

133kegiatan in the live demo (AY 2025/2026 and 2026/2027)
297RENSTRA 1.1 students, Setahun 2025/2026 (Ganjil 165 · Genap 132)
40RENSTRA 1.1 students, YTD 2026/2027
5indicators reported: 1.1, 1.1.a, 1.1.b, 1.19.S1, 1.19.S4

Figures from the import into the SIM Kerjasama Supabase project on 3 Oct 2026. The data is a demo set generated over the real SIM Kerjasama agreements and units, not real activities yet.

The problem it solves

IO currently learns about realizations from scattered reports, emails and spreadsheets. Counting inbound and outbound students, international activities and the share of agreements actually used means manual reconciliation every semester, and last semester's numbers can shift when late reports arrive.

What changes with the system

  • Each academic unit reports its own activities on one page, with the IA, IR and participant list attached.
  • Student numbers are checked against BAAK; no student is counted twice across units.
  • Numbers are computed by the database from verified data only, and each semester is frozen on its cutoff date.
  • Every list and report downloads as Excel, and every number drills down to the activities behind it.

Core ideas

TermMeaning
Kegiatan (activity)One realization event of one agreement, documented by exactly one Implementation Arrangement (IA) and one Implementation Report (IR). A multi-round programme submits one kegiatan per round.
Kerja samaThe single MoU/MoA from SIM Kerjasama the kegiatan implements, chosen from documents valid on the kegiatan dates, archived ones included.
Renewal chainAn agreement plus all its renewals. Realization of agreements (1.19.S4) counts chains, so a renewal mid-year is counted once.
Jenis KegiatanThe Agenda Kerjasama list from SIM Kerjasama. IO decides per agenda whether it is a mobility kegiatan (JD/DD, Student Exchange, Short/Summer, other) and whether it counts for 1.19.S1.
Mobility kegiatanNeeds a participant list and one PDF with transcripts, poster and documentation; verified by the IO Mobility team. Every other kegiatan is recorded as verified on submit.
SnapshotThe frozen indicator values of a semester, with the IDs of every record behind them and the settings used.

Business process

Two process models. The first follows one kegiatan from the unit to the numbers; the second covers what the system does on its own schedule. Both are available as .bpmn files that open in Bizagi Modeler (File → Import → BPMN).

2 · Pengingat, Tutup Semester & Pelaporan

Every day

Reminders for drafts near their reporting deadline (7 days before, on the day, then weekly) and for revisions left untouched 7 days. In-app plus email outbox.

R-61 R-62

On each semester cutoff

Semester end + 30 days: compute every indicator and the Awards, freeze them with the IDs behind each number, notify IO Admin and leadership. IO Admin can re-freeze with a written reason; the old snapshot stays, marked superseded.

R-55–R-59

Late data

A kegiatan verified or edited after a freeze but dated inside the frozen window is shown as Tambahan Susulan or Perubahan Pasca-Beku in YTD and the next report. Frozen numbers never change.

R-31 R-57

RENSTRA indicators and International Awards

Only verified kegiatan count, and the date that matters is the start date. Since Revisi V.2 every count is reported per unit: a Fakultas shows its own kegiatan plus the total of its Program Studi, and a Program Studi includes its Programs.

Jumlah mahasiswa Inbound & Outbound

Students per kegiatan, from the approved participant list of verified mobility kegiatan. Outbound kegiatan count PETRA students; inbound kegiatan count inbound students. Split into 1.1.a Inbound and 1.1.b Outbound.

R-38 R-39 R-40
1.19.S1

Kegiatan internasional berkolaborasi dengan mitra

Verified kegiatan whose Jenis counts for S1 and whose agreement has at least one foreign partner. The domestic count is shown alongside for reference.

R-41
1.19.S4

Persen terlaksana MoU & MoA

Share of agreements (renewal chains) used at least once in the academic year. Reported as one overall percentage, with All, International and Domestic splits. Internally still coded 1.19.24.

numerator = chains with ≥ 1 verified IA dated from AY start to the cutoff denominator = chains active in that window − chains whose first start is within 6 months of the cutoff (grace period, listed separately) + auto-renewed chains always included An MoA signed under an MoU is not a realization of the MoU.
R-42–R-47

Period cut-offs

Ganjil

Ganjil start → end. Read from its frozen snapshot once frozen.

Genap

Genap start → end, computed as of the full-year freeze so it never drifts.

Setahun (kumulatif)

Academic-year start → end. Read from the full-year snapshot.

YTD

Academic-year start → today. Never frozen, and offered only for the active academic year; other years fall back to Setahun.

International Awards

Ranks Program Studi only (Fakultas, Programs and support units are never ranked), using the same verified kegiatan, periods and duplicate rules as 1.1. Each student is credited to their own Prodi; an inbound student goes to the submitting unit when it is a Prodi.

  • Inbound, Outbound Dalam Negeri, Outbound Internasional boards, with columns JD/DD, Student Exchange, Short/Summer, and Kegiatan Internasional under 14 days.
  • Inisiatif Internasional: verified international kegiatan per submitting Prodi.
R-48 R-49 R-50

Reports and Excel

Laporan & Ekspor offers one report per indicator. The page preview and the Excel file come from the same query, so they always match.

  • Sheet 1: the per-unit table (or the overall percentage for 1.19.S4).
  • Sheet 2: the kegiatan or agreements behind it, with a Fakultas column.
  • Sheet 3 (1.1 family): the students, only for roles allowed to see them; logged as personal data.
  • Info sheet: filters, period, who exported and when.

What the data guarantees

  • One kegiatan, one agreement, one current IA and IR.
  • Only one approved participant list per kegiatan; earlier versions are kept.
  • A duplicate student is either open or decided for exactly one of the two kegiatan.
  • One live snapshot per year and period; re-freezing keeps the old one.
  • Nothing submitted is ever deleted; every change is in the Update Log.

Where the data comes from

  • Units, agreements, partners, countries and accounts: SIM Kerjasama, read live.
  • Student and employee names: BAAK and HR (mocked until PSI provides access).
  • Kegiatan, participants, files, verification and snapshots: entered in SIM Realisasi.

Architecture

One database, two systems. SIM Realisasi is deployed into the SIM Kerjasama Supabase project (simks-partnership, Postgres 17) in its own schemas. Business rules live in SQL so the screens, the Excel files and the frozen snapshots can never disagree. The Next.js app is a thin, role-aware UI over SQL functions.

Stack

  • Next.js 15 App Router, TypeScript, Tailwind, Radix/shadcn components, Recharts
  • react-hook-form + zod, schemas shared by client and server
  • postgres.js over DATABASE_URL (works on plain Postgres 16 and Supabase)
  • exceljs for every export, streamed from route handlers
  • pg_trgm, pgcrypto, pg_cron

Principles to keep

  • Overall status is derived in SQL, never set by the app.
  • Never write SIM Kerjasama tables or create objects in public; a test enforces it.
  • BAAK/HR only behind lookup_students / lookup_employees: production swaps the function body, nothing else.
  • Frozen means frozen: corrections create a superseding snapshot with a reason.
  • Page preview and Excel share one read model per report.

Run locally

npm install
cp .env.example .env.local
npm run db:reset   # SIMKS-shaped stub + migrations + seed
npm run dev        # http://localhost:3000

Node 22, Postgres 16 with pg_trgm and pgcrypto. Demo "today" is 2026-10-01; IO Admin can time-travel in Pengaturan to show cutoffs and reminders.

Tests

  • npm run test:db: 17 SQL suites covering the status machine, validation, every indicator, snapshots, RLS and access, jobs, duplicates, the SIMKS adapter, performance and Awards.
